# Куда класть тексты по игре Эйра

Ты сейчас работаешь в двух слоях одновременно:

1. **Код / прототип** — то, что делали через Codex: карта, точки, движение, интерфейс, события.
2. **Дизайн-документы / внутрянка** — правила мира и игры, по которым потом нужно наполнять код.

Эти файлы НЕ надо вставлять прямо в JS/HTML как есть. Их нужно положить в проект как документацию и постепенно превращать в данные.

## Рекомендуемая структура проекта

В корне проекта создай папку:

```text
/docs
```

В неё положи эти markdown-файлы:

```text
/docs/00_README_КУДА_ЭТО_КЛАСТЬ.md
/docs/01_Библия_игровой_системы.md
/docs/02_Разложение_мира.md
/docs/03_Шаблоны_контента.md
/docs/04_Промпт_для_Codex.md
```

Если у тебя проект уже лежит в VS Code, структура будет примерно такая:

```text
project-root/
  index.html
  src/
    ...
  data/
    ...
  docs/
    00_README_КУДА_ЭТО_КЛАСТЬ.md
    01_Библия_игровой_системы.md
    02_Разложение_мира.md
    03_Шаблоны_контента.md
    04_Промпт_для_Codex.md
```

## Что куда вставлять

### 1. `01_Библия_игровой_системы.md`

Это главный дизайн-док.

Он отвечает на вопрос:

> Как игра работает?

Туда кладём:
- базовую идею;
- цикл дня;
- перемещение;
- события;
- проверки;
- действия мира;
- фракции;
- Разломы и Печати;
- концовки.

Это не код. Это инструкция для нас и для Codex.

---

### 2. `02_Разложение_мира.md`

Это отдельный системный документ.

Он отвечает на вопрос:

> Как мир портится и как это влияет на игру?

Из этого документа потом надо сделать игровые переменные:

```js
worldDecay: 0,
personalDecay: 0,
sin: 0
```

И добавить их в состояние игры.

---

### 3. `03_Шаблоны_контента.md`

Это формы, по которым мы потом будем заполнять точки, события, NPC, фракции и квесты.

Например, когда мы будем писать точку карты, мы не будем писать “как получится”. Мы будем заполнять шаблон:

```text
Название точки:
Тип:
Описание:
Событие при входе:
Событие при отдыхе:
Версии события по уровню Разложения:
Возможные враги:
NPC:
Квесты:
Связи:
```

---

### 4. `04_Промпт_для_Codex.md`

Это не дизайн-док. Это инструкция, которую можно дать Codex.

Она нужна, чтобы Codex понял:

> Нужно не просто рисовать точки, а добавить в код игровые параметры Разложения мира, Sin и смену событий по уровню Разложения.

---

## Что делать прямо сейчас

Самый простой порядок:

1. В проекте создать папку `/docs`.
2. Положить туда эти файлы.
3. В Codex пока НЕ просить “сделай всю игру”.
4. Сначала попросить Codex добавить в состояние игры три параметра:

```js
worldDecay
personalDecay
sin
```

5. Потом попросить Codex сделать отображение этих параметров в интерфейсе.
6. Потом попросить Codex сделать, чтобы после кнопки “Следующий день” Разложение мира могло меняться.
7. Потом уже наполнять точки событиями, которые зависят от Разложения.

## Главное

Мы сейчас не “забыли про код”.

Мы делаем слой правил, который потом должен стать:
- частью состояния игры;
- частью событий;
- частью поведения фракций;
- частью концовок.

Без этого код будет просто картой с точками.
С этим код станет RPG-системой.
