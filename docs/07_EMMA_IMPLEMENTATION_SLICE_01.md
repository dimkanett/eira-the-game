# EMMA IMPLEMENTATION SLICE 01 — мельница, доставка муки, свободный порядок точек

## 0. Назначение файла

Этот файл — не полный сценарий Эммы. Это первый компактный кусок для реализации в коде.

Полный сценарный источник лежит в:

```text
/docs/06_EMMA_SCENARIO_SOURCE.md
```

Эта задача должна реализовать только первые 10–15 минут:

```text
выбор Эммы
→ локальная карта Железного Моста
→ мельница / дом Эммы
→ поручение развезти муку
→ свободный порядок посещения точек
→ первые бытовые сцены и флаги отношений
```

Не реализовывать сейчас:

```text
вечернюю развилку
ночную сцену
пропажу Томаса
серебряный мешок
ветку Рика и сетей
финалы A/B/C/D
старую переправу
боёвку
```

Главная цель: убрать рельсу. Игрок должен сам выбирать точки на локальной карте деревни, а не нажимать кнопки, которые автоматически гонят его по сюжету.

---

## 1. Ключевые правила реализации

### 1.1. Старт Эммы

При выборе Эммы игра должна сразу открывать локальную карту деревни, а не первое диалоговое окно.

Ожидаемое поведение:

```text
Игрок нажимает “Играть за Эмму”
→ mode = "location"
→ hero.location = "iron_bridge_village"
→ activeEvent = null
→ activeMessage = "Утро в Железном Мосту. Выбери, с чего начнётся день."
→ показана локальная карта деревни с точками
```

Для остальных персонажей оставить текущую логику старта.

### 1.2. Локальные действия

Клики по точкам локальной карты не тратят `actionsLeft`.

Глобальное перемещение по мировой карте по-прежнему тратит дневное действие.

### 1.3. После локального события

Если у выбранной ветки нет `nextEventId`, после результата игрок должен возвращаться к локальной карте, а не оставаться только с кнопкой “Следующий день”.

Практически:

```js
success: {
  text: "...",
  effects: [...]
  // no nextEventId => close activeEvent after result, stay in mode "location"
}
```

EventPanel может показать результат, но игрок должен видеть локальную карту и иметь возможность нажать другую точку.

### 1.4. Условия choices

Нужна поддержка:

```js
condition: { flag: "flag_name" }
condition: { notFlag: "flag_name" }
condition: { item: "item_id" }
condition: { notItem: "item_id" }
```

Если условия нет — вариант доступен всегда.

### 1.5. Динамический текст событий

Нужна поддержка:

```js
textVariants: [
  { condition: { flag: "some_flag" }, text: "..." },
  { condition: { notFlag: "some_flag" }, text: "..." }
]
```

EventPanel должен показывать текст через helper вроде:

```js
getEventText(gameState, event)
```

Если подходящего `textVariants` нет — показывать обычный `event.text`.

```js
if (effect.type === "inc_flag") {
  state.flags[effect.flag] = (state.flags[effect.flag] || 0) + effect.value;
}
```

## 5. Проверка завершения доставки

Пока не обязательно делать отдельный hub-event. Но желательно добавить helper/эффект, который после каждой доставки проверяет:

```js
flour_delivered_marta
flour_delivered_hagen
flour_delivered_oren
flour_delivered_oswin
```

Если все true:

```js
set_flag emma_deliveries_done = true
activeMessage = "Все заказы доставлены. Теперь Эмма может решить, куда пойти дальше."
```

Если быстро сложно — можно оставить это для следующего slice.

## 7. Ручной тест

После реализации проверить:

```text
1. Запустить игру.
2. Выбрать Эмму.
3. Сразу должна открыться локальная карта деревни, а не EventPanel с первым событием.
4. Нажать “Мельница Брана”.
5. Прочитать сцену утра.
6. Выбрать один из вариантов с отцом.
7. После результата должна быть доступна локальная карта.
8. Нажать точки в любом порядке: трактир, кузница, храм, староста, мост, берег.
9. Каждая точка должна открывать свою сцену.
10. Повторный клик по точке не должен полностью сбрасывать уже поставленные флаги.
11. Доставленная мука не должна доставляться второй раз, если есть условие notFlag.
12. Локальные клики не должны тратить actionsLeft.
13. Кнопка “Следующий день” не должна быть главным способом продолжения в location mode.
14. Глобальная карта должна оставаться рабочей.
15. NodeEditor через ?tool=node-editor должен открываться.
16. npm run build должен проходить.
```
